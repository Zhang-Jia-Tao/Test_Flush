字段约定：

| 字段 | 说明 |
| --- | --- |
| `type` | `announcement` 公告 / `news` 新闻 / `industry` 行业事件（三类；财务数据单独文件） |
| `occurredAt` + `occurredAtTz` | 原始时间戳与原始时区；故意混合 UTC、+08:00 |
| `source.tier` | A 监管/公司正式文件；B 主流媒体/第三方；C 传闻/自媒体（决定置信度） |
| `evidence[]` | 证据卡：原文摘录 kind=excerpt（必有）；可附 kind=document |
| `contentTags` | 数据预置标签：`fact` / `opinion`；`correlation` 与 `causal_hypothesis` 由系统生成，不预置 |
| `direction` | positive / negative / neutral，用于方向一致性 |
| `preMappedTradeDate` | 可选，人工预期映射日，测试中用于断言"映射结果 == 人工预期" |

事件类型扩充：`industry` 例（行业协会数据、政策发布、竞品事件）；`news` 例（券商评级=opinion、媒体报道=fact、网传截图=opinion+C 级来源）。

### 2.2 timeMapper.js（核心）

```js
// 工具：用 Intl 把任意 ISO 时间戳转换到交易所时区的 {date:'YYYY-MM-DD', minutesOfDay}
function getZonedParts(iso, timeZone) { /* Intl.DateTimeFormat 反解 */ }

// 主函数
function mapEventToTradeDate(occurredAt, occurredAtTz, cal, tz) {
  const { date, minutesOfDay } = getZonedParts(occurredAt, tz);
  // 1) 非交易日（周末/节假日/休市）→ 下一交易日
  if (!cal.isTradeDate(date)) {
    const next = cal.nextTradeDate(date);
    return { mappedTradeDate: next, phase: 'non-trading-day',
             reason: next ? '非交易日发生，顺延至下一交易日' : '超出交易日历范围',
             inRange: next !== null };
  }
  // 2) 交易日 15:00 切分（15:00:00 整归当日；≥15:00:01 归次日）
  if (minutesOfDay < 15 * 60) {
    const phase = minutesOfDay < 9*60+15 ? 'pre-market'
                : minutesOfDay < 15*60      ? 'trading-hours' : 'trading-hours';
    return { mappedTradeDate: date, phase, reason: '开盘前/交易时段发生，计入当日', inRange: true };
  }
  const next = cal.nextTradeDate(date);
  return { mappedTradeDate: next, phase: 'after-hours',
           reason: next ? '盘后发生，计入下一交易日' : '超出交易日历范围',
           inRange: next !== null };
}
```

边界用例（必须全部进测试）：

| 原始时刻（交易所本地） | 性质 | 映射日 |
| --- | --- | --- |
| 交易日 08:30 | 盘前 | 当日 |
| 交易日 09:15 | 开盘集合竞价起 | 当日 |
| 交易日 11:30–13:00 | 午休（仍是当日交易安排） | 当日 |
| 交易日 14:59:59 | 收盘集合竞价 | 当日 |
| 交易日 15:00:00 | 收盘整点 | 当日 |
| 交易日 15:00:01 / 15:05 / 19:30 | 盘后 | 下一交易日 |
| 周六任意时刻 / 周日任意时刻 | 非交易日 | 下一交易日（通常周一；周一是 holiday 则继续顺延） |
| 国庆假期内任意时刻 | 非交易日 | 节后首个交易日 |
| 区间之后 | 范围外 | null + inRange=false |

  // 基础分 → 方向归一（事件 positive/negative vs 异动 up/down）后：

  // → opinion 或 tier=C 封顶 0.3 → 浮点归一到两位小数

### 2.5 agent.js（规则助手）

```js
function analyze(date, ctx) {
  // ctx: bars, anomalies, mappedEvents（含财务），窗口 T-1~T+1
  const a = ctx.anomalyOn(date);
  if (!a) return { kind: 'normal-day', factors: [], message: '该交易日未达到异动判定标准（±7%）' };
  const cands = ctx.eventsMappedOn(date).concat(eventsOffset(date,-1)).concat(eventsOffset(date,+1));
  if (cands.filter(isFact).length === 0)
    return { kind: 'evidence-insufficient', factors: [], message: FIXED_TEXTS.insufficient };
  const factors = cands.map(e => buildFactor(e, a))
                      .filter(f => f !== null)
                      .sort(byScoreDesc).slice(0, 3);
  // 每个 factor 注入：模板措辞、置信度、不确定性、竞争解释、定位 eventId
  return { kind: 'anomaly', factors };
}
```

`FIXED_TEXTS`（固定文案库，开发时逐字实现）：

```
insufficient: 该交易日未检索到达到证据标准的可核实事件，无法给出可信归因。
              无明显消息面的异动也可能与资金面、市场情绪或技术因素有关，本演示未纳入这些数据。
causalTpl:    可能与《{title}》有关：该事件于{rawTime}（{phaseReason}）映射至{date}，
              与{direction}{movePct}在时间上相邻。依据：{evidenceText}。
              不确定性：{uncertainty}。该判断为因果假设，尚未经证实。
correlation:  同期发生，仅构成时间相关性，不构成因果关系。
disclaimer:   本页面为虚构模拟数据的教学演示，不构成任何投资建议。
```

### 2.6 schema.js（加载与校验）

- 逐文件 JSON.parse；错误捕获 → fatal error 状态（kline/stock 致命；其他文件致命或空态按文件定）。
- 逐条校验并收集 `{file, index, field, reason}`：bar 缺 OHLCV、价格关系非法、date 不在日历、时间戳无法解析、tier 非法、evidence 为空等。
- 返回 `{data, errors[]}`；坏行跳过并在 UI 显示"已跳过 N 条异常记录"。

## 4. 测试规格（断言级，tests/）

### 4.1 `timeMapper.test.js`

- T1 盘后：`2026-10-09T18:32:00+08:00`（周五）→ `2026-10-12`（周一），phase=`after-hours`。
- T2a 非交易日周末：`2026-10-17T10:00:00+08:00`（周六）→ `2026-10-19`（周一）。
- T2b 非交易日假期：`2026-10-03T10:00:00+08:00`（假期内）→ `2026-10-08`（节后首个交易日，按日历实际首日）。
- T4 边界：08:30→当日；09:15→当日；12:00（午休）→当日；15:00:00→当日；15:00:01→次日；15:05→次日。
- T5 时区跨日：`2026-10-09T16:30:00Z`（北京 10-10 00:30，周六）→ `2026-10-12`；`2026-10-09T01:30:00Z`（北京 09:30）为交易日则当日。
- 范围外：区间最后一个交易日之后的盘后事件 → `inRange=false`、mappedTradeDate=null。

### 4.2 `anomaly.test.js`

- T6a：close 由 11.84 → 12.86（+8.6%）→ 命中 up，triggers 含 `threshold+7%`。
- T6b：−7.0% 整与 −6.99% 边界（阈值含等号）。
- T6c：量比 3.0 整命中 volumeSurge；2.99 不命中。
- T6d：手工 anomalyTag='down' 而规则未命中 → 仍输出，triggers 含 `manualTag`。
- 前 30 日不足时均量按可得窗口计算。

### 4.3 `agent.test.js`

- T3a 证据不足（核心）：T_weak 窗口事件仅含 C 级 opinion（或零事件）→ 返回 `kind:'evidence-insufficient'`，factors 为空，message 为固定文案；断言输出中**不得**出现"导致/推动/因为"字样。
- T3b：T_up 同时有合同公告（A 级、positive）与关税消息（B 级、negative）→ 主因素为合同（置信度高、排序第一），且结果中包含竞争解释（关税列为低排序因素或不确定性提示）。
- T3c：普通日 → `kind:'normal-day'`。
- 因素上限：构造 5 条候选 → 输出 ≤3。
- 措辞断言：所有因果因素文案包含"可能与""因果假设""尚未经证实"；相关性文案包含"时间相关"。

### 4.4 `schema.test.js`

- T7：缺 high / 非法日期 / close 非数字 → 各产生 1 条 error，坏行被剔除，其余正常加载。
- 事件 occurredAt 非法、tier 非法、evidence 为空 → 报错定位到 id。
- 空文件（[]）→ 不抛错，进入 empty 状态数据。

运行：`node --test tests/`（Node ≥18，零依赖）。
