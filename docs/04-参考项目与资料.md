## A. 直接同类产品 / 开源项目（重点参考）

### A1. K-Ray —— A 股涨跌原因复盘工具（最接近的同类产品）

- 是什么：TRAE AI 创造力大赛作品，金融研究员个人开发的 A 股复盘 Web 产品。真实日 K + 自动识别"单日显著上涨/下跌、阶段高点/低点" + 点击节点展示当日涨跌幅、成交量、板块表现、复盘摘要及公告/新闻/政策/市场资料（保留来源名称、发布时间、原文链接），另有静态历史案例（内置案例、无需联网即可体验）。
- 技术栈：Next.js 16 + React 19 + TypeScript + Tailwind CSS + **Lightweight Charts** + Python BaoStock + Vercel；37 个测试套件、1370 项测试。
- 借鉴点：
  1. "关键节点 → 事件资料 → 来源溯源"的交互闭环与本项目几乎一致，可对照其信息架构；
  2. **静态案例**解决开箱体验问题——与本题"自包含模拟数据"要求一致，证明路线可行；
  3. 非代码作者用"阶段验收 + 自动测试 + 截图"管理复杂项目的做法；
  4. 它依赖真实数据/Next.js，本项目反其道而行：零构建 + 虚构数据 + ECharts，形成差异化。
- 链接：
  - 介绍帖（含完整实践过程与截图）：https://forum.trae.cn/t/topic/166091
  - GitHub：https://github.com/GreMed/k-ray
  - 在线 Demo：https://k-ray.vercel.app/ （核心静态案例：/demo/core-replay?stock=300750）

## B. 学术论文（方法论与护栏）

### B1. Stock Pattern Assistant（SPA）★最重要

- *Stock Pattern Assistant: A Deterministic and Explainable Framework for Structural Price Run Extraction and Event Correlation in Equity Markets*，arXiv:2512.15008
- 借鉴点（本项目的方法论骨架）：
  - 确定性管道：OHLCV 清洗 → 收益/方向标记 → 单调 run 检测 ‖ 事件标准化（时区统一、交易日历对齐、去重、schema 标准化）→ 对称时间窗（δ=1~3，默认 2）对齐 → 受约束解释层；
  - 明确"对齐仅为时间相关，不做因果归因"，解释层护栏：禁预测、禁因果措辞、只用输入字段、确定性可审计；
  - 无事件时如实报告"信息稀疏"；事件密度指标；
  - 评估同样使用 curated timestamped 样本数据、时间戳统一交易所时区——与本题模拟数据路线一致。
- 链接：https://arxiv.org/pdf/2512.15008v1

### B2. Trade the Event（事件驱动交易）

- *Trade the Event: Corporate Events Detection for News-Based Event-Driven Trading*（ACL 2021），含 EDT 数据集（30 万+篇分钟级时间戳新闻）。
- 借鉴点：事件是价格运动的驱动力这一建模思想；事件类型体系（公司事件分类）；分钟级时间戳意识。
- 链接：https://arxiv.org/pdf/2105.12825.pdf ；代码：https://github.com/Zhihan1996/TradeTheEvent

### B3. Market-Aware Event Timeline Summarization（AAAI）

- 价格信号 + 新闻时间线摘要系统：回溯式"在价格图旁边探索事件"，LLM 生成背景摘要。
- 借鉴点：时间线与图表并排的叙事逻辑；"事件时间线服务于理解波动"的产品论证。
- 链接：https://ojs.aaai.org/index.php/AAAI/article/download/42370/46331

### B4. 事件研究法综述（Event Study）

- MacKinlay 传统事件研究法的现代综述：AR = R − E[R]，CAR 与显著性检验。
- 借鉴点：03 文档阈值设计的学术背景；README 已知限制（为何固定阈值不等于严格异常收益检验）。
- 链接：https://arxiv.org/html/1506.02431v2

### B5. 极端收益定义（Extreme Return / Tail Event）

- 用滚动窗口分位数（如 252 日 1% tail）定义极端收益，避免绝对阈值跨股票不可比。
- 借鉴点：未来扩展方向（自适应阈值）；03 文档中阈值局限的论据。
- 链接：https://www.extremereturn.com/ ；https://amstat.tandfonline.com/doi/full/10.1080/15427560.2026.2620420

## E. 调研中识别的"不要做"清单（避坑）

1. 不要把时间相关性写成因果——SPA 论文与财经鉴真技能都把它列为第一护栏；本项目因果假设必须显式带置信度与不确定性。
2. 不要把"无法证实"写成"证伪"——Unsupported ≠ False；证据不足用例必须如实呈现。
3. 不要依赖运行环境时区——所有时间转换显式传 `Asia/Shanghai`，测试跨机器可复现。
4. 不要选需要构建链的重型框架去满足一个静态演示需求——K-Ray 用 Next.js 是因为它有真实 API 与多页面；本项目零数据依赖，零构建最稳。
5. 不要引入真实行情接口——题目明确排除；"接口不可用导致演示翻车"是 K-Ray 作者特意用静态案例规避的问题，本项目直接内置虚构数据。
6. 不要让 Agent 输出预测/投资建议——页面固定免责声明，措辞模板化。
