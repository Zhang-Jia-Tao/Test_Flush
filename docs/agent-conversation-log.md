> 题目见 Plan.md（"股价异动解释时间线"）。先整体分析需求并拆分需求，详细分析哪部分需要搜索网络资料；先搭建针对该需求的基础知识库并搜索 GitHub 中相关内容，尤其是相关的 Agent、Skill、插件或项目；以"候选人提交要求"为基础前提；先做第一步——需求分析与拆解、知识库搭建。

### Agent 执行过程

1. **探查**：读取 `F:\PythonProject\Plan.md`（题目原文）与目录现状（仅 main.py 模板文件）。
2. **建立任务清单**：需求拆解 / 网络资料调研 / GitHub 项目调研 / 知识库文档落地。
3. **联网调研（共 5 轮检索 + 3 次全文精读）**，关键发现：
   - 图表库：ECharts 原生 candlestick + markPoint + click/dispatchAction/connect 事件联动体系最成熟；Lightweight Charts（K-Ray 同款）最轻但事件标记能力弱；KLineChart/HQChart 偏重。
   - 交易时段【交易所规则原文】：9:15-9:25 开盘集合竞价、9:30-11:30/13:00-14:57 连续竞价、14:57-15:00 收盘集合竞价；盘后固定价格 15:05-15:30（2026-07 扩至全部 A 股）。
   - 信披时段：盘后披露窗口（15:30 至次日 8:30 等）、非交易日最后一日下午窗口——为"盘后/周末公告"模拟数据提供真实依据。
   - 异动阈值：龙虎榜主板 ±7% 偏离值、振幅 15%、换手 20%；恒生聚源异动归因技能个股阈值同为 7%、量比 3 倍、事件窗 T−1~T+1；学术事件研究法 AR/CAR 作为背景。
   - 最有价值的学术参考：arXiv:2512.15008（SPA，确定性价格 run + 事件对称窗对齐 + 护栏式解释：禁因果措辞、无事件如实报告、时区统一、确定性可审计）。
   - 最有价值的同类产品：K-Ray（TRAE 大赛，Next.js + Lightweight Charts，自动识别显著涨跌节点 + 事件资料 + 来源溯源 + 静态案例），GitHub: GreMed/k-ray。
   - 标注框架：财经新闻鉴真技能的事实/观点信号词、证据 A–E 分级、置信度 6 档、"因果崩溃"反模式；学术核查传统（claim/non-claim、Unsupported ≠ False）。
   - 浮动助手：assistant-ui AssistantModal 的 FAB + Portal 浮层范式（原生 DOM 复刻）。
   - 时区技术：原生 Intl.DateTimeFormat 可零依赖完成且测试可复现；测试选 Node 内置 node:test。
4. **产出 6 份文档**（docs/）：00 索引、01 需求拆解、02 技术选型、03 领域规则、04 参考资料、05 数据结构与规则设计。

### 本阶段关键决策（及理由）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 零构建静态站点（原生 JS + ECharts），不采用 K-Ray 的 Next.js 方案 | 题目要求自包含、无服务端、模拟数据；评审双击/静态服务器即可运行；核心逻辑与 UI 解耦后仍可写单元测试 |
| D2 | ECharts 而非 Lightweight Charts | 本题核心在"事件标记 + 四向联动"，ECharts markPoint/scatter/action 体系直接支持，开发量最小 |
| D3 | 模拟标的设为沪市主板（±10% 涨跌幅），异动阈值 ±7% | 7% 是龙虎榜与产业实践双重交叉验证的口径；落在"明显异动但不必然涨停"区间，叙事空间大 |
| D4 | 15:00 为盘前/盘后切分点，15:00:00 归当日 | 收盘集合竞价 15:00 结束，之后信息不影响当日成交；与题目"盘后映射下一交易日"一致 |
| D5 | 事件窗口 T−1~T+1，因果置信度上限 0.9 | 聚源消息面窗口与 SPA 对称窗（δ=1~3）交叉验证；禁止出现"确定"口径 |
| D6 | 预埋三个异动日：T_up（盘后公告）/T_down（周末利空）/T_weak（仅传闻） | 分别覆盖盘后、非交易日、证据不足三个必测用例 |
| D7 | 测试用 node:test 而非 Vitest/Jest | 零依赖、ESM 原生、与自包含目标一致；核心模块为纯函数，浏览器与 Node 共用 |
| D8 | 时间戳故意混合 UTC 与 +08:00 | 题目明确要求时区转换展示，混合来源才能验证转换链路 |
