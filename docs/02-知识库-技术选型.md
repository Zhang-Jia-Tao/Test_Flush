## 1. K 线图库选型

### 1.1 候选对比

| 维度 | Apache ECharts | Lightweight Charts（TradingView） | KLineChart | HQChart |
| --- | --- | --- | --- | --- |
| 定位 | 通用图表，原生 candlestick | 专为金融图表设计 | 国产轻量金融图表 | 国产专业行情图（对标通达信） |
| K 线能力 | 原生蜡烛图 + 双 grid 成交量、dataZoom、markPoint/markLine | 原生 candlestick，canvas 渲染性能好 | 原生 + 内置大量技术指标 | 指标/画线最全 |
| 事件标记 | markPoint + 自定义散点系列，交互事件成熟 | `setMarkers`（仅 up/down/coin 简单形状，挂数据点） | 需自定义覆盖物 | 需按其 API 二次开发 |
| 点击/高亮 API | `chart.on('click')`、`dispatchAction({type:'highlight'/'downplay'})`、`echarts.connect()` 多图联动 | `subscribeClick(seriesType, handler)`，高亮需自己管 | 有订阅 API，文档相对少 | 较重 |
| 体积 | 较大（可按需引入，完整版约 1MB，gzip 约 350KB） | gzip 约 45KB，最轻 | gzip 约 50KB，零依赖 | 大 |
| 无构建使用 | 可直接 `<script src>` / ES module CDN | 提供 standalone UMD/ESM | 可 script 引入 | 可 script 引入 |
| License | Apache-2.0 | Apache-2.0（需保留版权声明） | Apache-2.0 | 自定义开源协议 |
| 与本项目匹配度 | **高** | 中（事件标记与时间线联动要额外开发） | 中（指标用不上） | 低（过重） |

来源：
- ECharts 事件与动作官方手册（已查证）：https://apache.github.io/echarts-handbook/en/concepts/event/
- ECharts `on/off`、`dispatchAction`（highlight/downplay）、`connect` API（已查证）：https://www.mintlify.com/apache/echarts/api/on-off 、https://www.mintlify.com/apache/echarts/api/dispatch-action 、https://www.mintlify.com/apache/echarts/api/connect
- 图表库横向对比（实践参考）：https://chenguangliang.com/posts/blog152_react-chart-libraries-comparison/
- Lightweight Charts 定位与体积（实践参考）：https://www.index.dev/skill-vs-skill/tradingview-vs-lightweight-charts-vs-chartjs
- KLineChart 官网（已查证）：https://klinecharts.com/
- 同类产品 K-Ray 选用 Lightweight Charts（Next.js 技术栈，实践参考）：https://forum.trae.cn/t/topic/166091

### 1.2 结论：ECharts 5

理由：

1. **题目交互核心是"事件标注 + 四向联动"**：ECharts 的 markPoint/自定义散点 + click 事件 + `dispatchAction` 高亮/`showTip` 是为这类场景设计的；Lightweight Charts 的 markers 表达能力弱，事件形状、点击命中、时间线联动都要自己写插件，反而更慢。
2. **零构建友好**：单个 `echarts.min.js` 本地 vendored，双击 HTML 即可运行，符合"自包含、可复现、无服务端"。
3. **成交量副图、dataZoom 缩放**开箱即用，无需指标生态（本项目不做技术指标）。
4. 引入方式：**本地 `vendor/echarts.min.js` 为主，CDN 为辅**（`<script>` 先试 CDN、失败回退本地，或直接只用本地，保证完全离线可用）。

实现要点（已查证 API）：

- K 线：`series.type='candlestick'`，数据项 `[open, close, low, high]`；成交量用第二个 xAxis/yAxis grid 的 bar。
- 异动高亮：`markPoint`（箭头/图钉 + 标签）+ 选中日 `dispatchAction({type:'highlight', dataIndex})` 与非选中日 `downplay`；也可给选中蜡烛所在 x 轴位置加 `markArea` 背景带。
- 事件图标：在 K 线下方/最高价上方叠加 `scatter` 系列，按事件类型分 symbol/color；点击 scatter 命中即打开详情。
- 点击蜡烛：`chart.on('click', params => params.dataIndex → tradeDate)`。
- 缩放：`dataZoom`（inside + slider），时间线滚动范围跟随可视区间（可选增强）。

## 2. 浮动 Agent 助手 UI

调研结论（实践参考）：

- 成熟范式 = **FAB（Floating Action Button，固定右下角圆形按钮）+ Popover/Modal 浮层（Portal 挂载到 body）**，代表实现 assistant-ui 的 `AssistantModal`：fixed 定位触发按钮、点击在 portal 中渲染聊天面板、可调整尺寸。
  - https://www.assistant-ui.com/docs/primitives/assistant-modal
  - https://www.assistant-ui.com/elements/assistant-modal
- 同类 vanilla JS 方案（Persona）证明"角落 launcher + 浮动面板"不依赖 React 也成立：https://www.persona-chat.dev/
- AG-UI（Agent-User Interaction Protocol，GitHub 16k★）定义了前后端 Agent 事件协议：本项目**不接入**（无后端、无流式对话），仅参考其"事件化消息"思想。

本项目实现（原生 DOM，不引 React）：

- 右下角 56px 圆形按钮（Agent 图标 + 未读/状态点）；点击展开约 380×520 面板，遮罩可选不用（避免遮挡 K 线）。
- 面板结构：标题栏（"异动解释助手（模拟规则）" + 免责声明入口）→ 选中日摘要（日期、涨跌幅、量比）→ 1~3 张因素卡（标签色条 + 标题 + 依据 + 置信度条 + 不确定性提示 + "定位事件"按钮）→ 底部固定提示"演示项目，所有内容为模拟数据，不构成投资建议"。
- 切换选中日时，面板内容带淡入动画并更新；未选择日期时显示引导态。
- 置信度用三色进度条（高≥0.7 绿 / 中 0.4–0.7 黄 / 低<0.4 灰红），低置信度必须显示感叹号与"未经证实"字样。

## 3. 事件时间线：自研 DOM 而非 vis-timeline

- vis-timeline（canvas fork 版可承载数万 item）适合甘特/大规模时间轴，但它自带时间轴渲染与滚动体系，与 ECharts 的日期轴**双向同步成本高**，样式定制也重。
- 本项目事件规模仅数十条、分组逻辑特殊（按"映射交易日"分组而非自然时间轴，且需与 K 线日期一一对应），**原生 DOM + CSS 纵向时间线**更可控：
  - 每个交易日一个分组节点（日期 + 星期 + 该日 K 线小徽标：涨跌色），组内按时间排列事件卡（类型图标 + 标题 + 标签 + 来源 + 映射原因）。
  - 选中异动日 → `scrollIntoView({behavior:'smooth', block:'center'})` + 高亮 class；点击卡片 → 详情面板。
  - 范围外事件单独灰色分组。
- 可访问性：事件卡用 `<button>`，支持键盘 Enter；标签用文字 + 颜色（不只靠颜色区分）。

## 4. 时间与时区处理

- 浏览器原生 `Intl.DateTimeFormat({timeZone:'Asia/Shanghai', ...})` 可完成任意时区到目标时区的日期时刻提取，所有现代浏览器（2017 年起）支持，无需引库（已查证，MDN）：https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat
- `date-fns-tz` 的 `toZonedTime/formatInTimeZone` 更方便，但会引入依赖；本项目时区固定、规则简单，**自写约 30 行 `getZonedParts(ts, tz)` 工具函数**（基于 Intl 格式化反解）即可，零依赖且可直接在 Node 中测试。
- 存储约定：所有事件时间戳用带偏移的 ISO 字符串（如 `2026-09-19T12:30:00Z` 或 `2026-09-19T20:30:00+08:00`），不在前端用"无时区字符串"。
- 测试注意（已查证，Vitest 官方文档）：Worker 线程中设置 `process.env.TZ` 不一定生效；因此**不依赖运行环境时区**，所有转换显式传入 `Asia/Shanghai`，保证测试在任何机器、任何时区下结果一致：https://cn.vitest.dev/guide/common-errors.html
- 模拟数据统一用 Asia/Shanghai（UTC+8，无夏令时），降低理解成本；但事件流故意混入 UTC 时间戳以验证转换。

## 5. 测试方案：Node 内置 test runner

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| `node:test` + `node:assert`（Node ≥18） | 零依赖、零安装、与 ES module 原生兼容、CI 简单 | 无 Web UI | **选用** |
| Vitest | 生态好、watch 模式、可测 DOM | 需要 npm install，与"自包含"目标有摩擦 | 备选（若后续引入 jsdom UI 测试再升级） |
| Jest | 成熟 | 配置重、ESM 支持麻烦 | 不选 |

关键前提：**核心逻辑（calendar/timeMapper/anomaly/evidence/agent/schema）写成纯 ES module，不引用 `window`/`document`/echarts**，浏览器与 Node 共用同一份代码。`package.json` 仅保留：

```json
{
  "scripts": { "test": "node --test tests/" }
}
```

## 6. 最终技术栈与项目结构

- 技术栈：**原生 HTML + CSS + JavaScript（ES2020 modules）+ Apache ECharts 5**；无框架、无构建、无后端、无 npm 运行时依赖。
- 运行：`python -m http.server 8000`（推荐，ES module 需 http 协议）后访问 `http://localhost:8000/`；README 同时给出 VS Code Live Server 方式。
- 测试：Node ≥18，`npm test`（仅用内置模块，不需要 `npm install`）。

## 7. 选型风险与备选

| 风险 | 应对 |
| --- | --- |
| 本地 file:// 打开时 ES module 被 CORS 拦截 | README 明确用 http.server；另提供"全内联单文件版"作为可选交付（构建脚本把 data 与 js 内联），优先保证常规方式 |
| vendored ECharts 完整版体积偏大 | 先用完整版保证功能；如评审在意体积，再用 echarts 自定义构建（只含 candlestick/bar/scatter/grid/dataZoom/markPoint/tooltip） |
| 原生 JS 项目组织不善会变乱 | 严格 core/ui 分层 + 单一 app.js 装配 + 纯函数测试兜底，文档中固化模块边界 |
| 评审机器没有 Node | 测试为加分项；网页本身不依赖 Node，Python 静态服务器即可（也给出直接双击运行的内联备选） |
