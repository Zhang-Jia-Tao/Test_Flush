# 01 · 需求分析与拆解

> 项目：股价异动解释 Agent（K 线与事件时间线 + 浮动 Agent 助手）
> 文档定位：开发前的需求基线。后续所有设计、实现、测试均以本文的验收点为准；需求变更须更新本文。
> 版本：v1.0（2026-10-21）

---

## 1. 一句话理解需求

做一个**纯前端、自包含、可复现**的网页：用户在 K 线图上点选某个"明显上涨/下跌"的交易日，系统把该日前后的行情、公告、新闻、行业事件、财务数据组织成一条**可交互事件时间线**，并由一个**浮动 Agent 助手**按"事实 / 观点 / 时间相关性 / 因果假设"四层口径，给出 1~3 个**带证据、带置信度、带不确定性提示**的可能影响因素。

关键定性：这是一个**历史解释（explain / hindsight）**产品，不是预测产品、不是投顾产品。所有因果表述都必须是"尚未证实的假设"。

---

## 2. 产品形态与页面结构

推荐形态题目已经给定：**K 线 + 事件时间线 + 浮动 Agent 助手**。页面拆为 5 个区域：

| 区域 | 内容 | 必备交互 |
| --- | --- | --- |
| A. 顶部信息栏 | 虚拟股票名称/代码、交易所、时区、数据区间、图例说明 | 重置选择、状态提示入口 |
| B. K 线图区 | 日 K 蜡烛图（主图）+ 成交量（副图）；异动日明显高亮（配色/标注/箭头）；事件可在 K 线下方以小图标标记 | 点击任意交易日 → 选中该日；点击异动日 → 触发联动；缩放/平移 |
| C. 事件时间线 | 按"映射交易日"分组的纵向时间线；事件按类型分色/图标；与选中日相关的事件自动滚动定位并高亮 | 点击事件 → 在 D 区打开详情；点击因素定位 |
| D. 事件详情面板 | 标题、发布时间（**原始时间 + 交易所时区时间 + 映射交易日**）、类型、来源、摘要、证据列表（证据等级/摘录/链接）、内容标签（事实/观点/…） | 关闭、在时间线中定位、关联跳转 |
| E. 浮动 Agent 助手 | 右下角悬浮按钮 → 弹出面板；随选中日变化，输出 1~3 个可能影响因素；每条含分类标签、依据、置信度、不确定性提示、"定位到对应事件"按钮 | 展开/收起、定位事件、无选中日时引导 |

联动主线（必须闭环）：

```
点击 K 线异动日
   ├─ K 线高亮该蜡烛（其余压暗）
   ├─ 时间线自动滚动到该交易日分组，高亮相关事件（T-1 ~ T+1 窗口）
   ├─ 详情区默认展示该日最相关的一条事件（或汇总卡）
   └─ 浮动助手基于该日重新生成 1~3 个因素
点击时间线事件
   ├─ 详情区打开该事件
   └─ K 线定位到该事件映射的交易日
点击助手中"定位事件"
   └─ 时间线高亮并滚动到对应事件卡片
```

## 3. "必须完成"逐条拆解与验收点

| # | 题目要求 | 拆解为可验收的点 |
| --- | --- | --- |
| 1 | 可交互网页，含 K 线/收盘价图、事件时间线、事件详情、浮动助手 | ① 单页应用，浏览器直接打开可运行；② 四区齐全（B/C/D/E）；③ 无后端、无联网依赖也能完整运行 |
| 2 | 识别或预先标记至少一个明显上涨/下跌交易日并突出显示 | ① 数据中至少预埋 1 个显著上涨日、1 个显著下跌日（建议各 1~2 个，共 2~3 个）；② 异动日在 K 线上有醒目且唯一的视觉样式（如红/绿描边 + 顶部箭头 + "涨/跌 X%"标签）；③ 异动既可由规则自动识别，也允许数据中手工预标记，两者结果需一致并在规则说明中给出 |
| 3 | K 线与时间线联动；事件可查看标题、发布时间、类型、来源、摘要、证据 | ① 见第 2 节联动闭环，逐路径可点验；② 事件详情 6 个字段一个不缺；③ 证据至少包含来源等级、原文摘录、可点击来源标识（模拟链接即可） |
| 4 | 事件时间统一转交易所时区；盘前/盘中→当日，盘后/非交易日→下一交易日 | ① 事件原始时间戳保留（含原始时区）；② 显示转换后的交易所时区时间；③ 映射规则见第 5.2 节，边界点（9:15、11:30、13:00、15:00）有明确约定；④ 非交易日（周末/节假日）顺延到下一交易日；⑤ 映射结果在详情中可见、可人工核对 |
| 5 | 标注"事实/观点/时间相关性/因果假设"；因果假设须展示依据、置信度、不确定性，不得呈现为已证实 | ① 每条事件/解释至少带一个分类标签；② 因果假设卡必须同时具备：依据（关联证据）、置信度（高/中/低 + 分值）、不确定性提示文案；③ 全文案禁止"导致/推动/因为该事件所以涨停"等确定性归因措辞，统一使用"可能与……有关""同期发生" |
| 6 | 浮动助手按选中日给 1~3 个因素，可定位到事件；规则/预设/模拟均可 | ① 无选中日：引导选择；② 普通日：可提示"该日未达异动标准"；③ 异动日：输出 1~3 条因素，每条可点击定位；④ 因素数量不足时如实输出（允许 0 条并说明"未发现可核实因素"），禁止硬凑 |
| 7 | 加载、空数据、时间范围外事件、异常数据状态提示 | 四种状态均有明确 UI（见第 6 节），并能通过模拟数据/开关复现 |

## 4. 数据需求拆解（全部内置、模拟、可复现）

建议 6 个数据文件，放 `data/`：

| 文件 | 内容 | 关键字段（草案，详见 05 文档） |
| --- | --- | --- |
| `stock.json` | 虚拟股票元信息 | 虚构名称、代码（建议沪市主板 600xxx 形态）、交易所（SSE）、时区（Asia/Shanghai）、板块、涨跌幅限制、异动阈值配置 |
| `calendar.json` | 交易日历 | 区间内全部交易日数组；节假日/休市数组；用于非交易日顺延 |
| `kline.json` | 日 K 行情 | 日期、open/high/low/close、volume、（可选）成交额；约 30~45 个交易日 |
| `events.json` | 统一事件流：公告、新闻、行业事件 | 事件 id、类型、原始时间戳（**故意混合 UTC 与 Asia/Shanghai**）、标题、来源、来源等级、摘要、正文证据摘录、模拟链接、预置内容标签 |
| `financials.json` | 财务数据 | 报告期、披露时间戳（用于时间映射）、营收/净利润/同比等 2~3 项指标 |
| `manifest.json`（可选） | 数据清单与版本 | 各文件校验信息、数据生成说明，便于"可复现"验收 |

模拟场景设计要求（为测试与演示服务，而非随机）：

1. **显著上涨日（T_up）**：前一交易日**盘后**发布重大合同/业绩预告公告（覆盖"盘后事件→次日"映射）。
2. **显著下跌日（T_down）**：落在**周一**，其**周六/周日**出现行业性利空政策事件（覆盖"非交易日事件→下一交易日"）。
3. **证据不足异动日（T_weak）**：明显涨跌但窗口内只有一条"网传/消息人士"类**观点**或干脆没有事件——用于检验助手是否如实输出"证据不足"，而非编造因果。
4. **时区跨日事件**：一条以 UTC 记录的海外行业事件，转换到北京时间后跨日（覆盖时区转换）。
5. **范围外事件**：1~2 条事件映射日落在 K 线区间之外（用于第 7 类状态）。
6. **坏数据**：单独提供一份"异常数据"演示数据集（或 URL 参数开关），包含缺字段、非法日期、非数字价格。
7. 交易日历须显式包含周末与至少一个连续假期（如自造"国庆"休市段），让非交易日顺延有区分度。

## 5. 规则引擎拆解（项目的"大脑"，与 UI 解耦）

所有规则写成**纯函数模块**（`src/core/`），不依赖 DOM、不依赖图表库，浏览器和 Node 测试共用同一套代码。

### 5.1 异动判定（anomaly）

- 主规则（固定阈值，可在 stock.json 配置）：
  - 显著上涨：日涨跌幅 ≥ **+7%**；显著下跌：≤ **−7%**（阈值依据见 03 文档：龙虎榜主板 ±7% 偏离值口径、行业实践个股 7% 口径）。
  - 辅助信号：当日成交量 ≥ 前 30 个交易日均量 × **3**（数据不足时按可得窗口）。
- 允许数据中手工预标记 `anomaly: true`，规则识别结果与预标记取并集并在 UI 注明来源（自动识别/人工标记）。
- 输出：异动方向、涨跌幅、量比、触发的规则、（可选）连续 3 日累计偏离标记。
- 明确不做：市场模型/异常收益（AR）回归、复杂技术指标（题目范围约束排除）。03 文档会说明阈值与学术事件研究法（AR = 实际收益 − 期望收益）的关系，作为设计依据而非实现项。

### 5.2 时区与交易日映射（timeMapper）—— 核心规则

- 内部统一存储 ISO 8601 带偏移时间戳；显示时统一转换到交易所时区（模拟数据用 `Asia/Shanghai`，UTC+8 无夏令时）。
- 交易所时间轴（依据沪深交易所 2026 修订交易规则，见 03 文档来源）：
  - 9:15–9:25 开盘集合竞价；9:30–11:30、13:00–14:57 连续竞价；14:57–15:00 收盘集合竞价；15:05–15:30 盘后固定价格交易。
- 映射规则（**以交易日历为准**）：
  1. 事件先转到交易所时区，得到"本地日期 + 本地时刻"。
  2. 本地日期是交易日，且时刻 **< 15:00:00**（盘前 0:00–9:15、盘中含午休）→ 映射**当日**。
  3. 本地日期是交易日，但时刻 **≥ 15:00:00**（含盘后固定价格时段及晚间披露）→ 映射**下一交易日**。
  4. 本地日期是非交易日（周末/节假日/休市）→ 映射**下一交易日**，不论时刻。
  5. 边界：15:00:00 整归当日；15:00:01 起归次日（午间休市 11:30–13:00 仍归当日，因其影响午后交易）。
  6. 映射日超出 K 线/日历区间 → 标记"时间范围外"，进入特殊状态，不参与异动归因。
- 每条事件产出三个时间字段：`occurredAtRaw`（原始）、`occurredAtExchange`（转换后）、`mappedTradeDate`（映射交易日）+ 映射原因（盘前/盘中/盘后/非交易日顺延）。

### 5.3 证据与内容标注（evidence）

四类标签（详细判据与示例见 03 文档）：

| 标签 | 判据 | 数据中的来源 |
| --- | --- | --- |
| 事实 fact | 可客观验证、有权威来源的已发生事项（公告原文、财报数字、监管文件） | 公告、财务数据 |
| 观点 opinion | 主观判断、预测、评级、传闻（"有望""预计""据传"） | 分析师评论、媒体解读、自媒体 |
| 时间相关性 correlation | 事件落在异动日映射窗口（T−1~T+1）内，仅陈述"时间上同时/邻近发生"，不含因果 | 系统计算生成 |
| 因果假设 causal_hypothesis | 系统对"可能影响因素"的推断；必须携带 evidenceIds、confidence、不确定性说明 | Agent 生成 |

证据分级（简化为 3 级，供置信度计算，完整 5 级体系见 03 文档）：

- A 级：交易所/监管机构/公司正式公告、经审计财报（权重高）
- B 级：主流财经媒体、行业协会/第三方统计
- C 级：匿名传闻、自媒体、社交媒体（不能单独支撑因果假设）

### 5.4 规则 Agent（agent）

确定性规则实现（输入相同 → 输出相同），不调用真实模型：

1. 取选中日 D，收集映射日 ∈ [D−1, D+1] 的全部事件 + 当日及最近财务数据。
2. 为每个候选因素计算：相关度（类型权重：公告 > 财务 > 行业事件 > 新闻；时间距离：当日 > 前一日 > 后一日）、证据强度（来源等级、证据条数）、方向一致性（利好/利空与涨跌方向是否一致）。
3. 输出 1~3 个因素；每个因素 = {标题、标签（事实/观点/相关性/因果假设）、关联事件 id、依据要点、置信度（高≥0.7 / 中 0.4~0.7 / 低<0.4）、不确定性提示}。
4. 护栏（来自 SPA 论文与财经鉴真方法论，见 03 文档）：
   - 无事件窗口 → 输出"未发现可核实事件，当前仅能确认时间相关性不足/无相关"，**禁止编造**；
   - 仅有观点/传闻 → 最多给"低置信度"因素且明示"未经证实"；
   - 存在多个竞争解释 → 全部列出，不得单选并断言；
   - 措辞统一为"可能与……有关""同期出现"，禁止"导致/造成"；
   - 不做预测、不给投资建议；面板底部固定免责声明。

## 9. 范围边界（做什么 / 不做什么）

**做**：单只虚拟股票、日级 K 线、确定性规则 Agent、四类标签、四类状态、时区映射、测试、文档。

**不做**（题目明确排除或刻意收敛）：

- 不接真实行情/新闻 API、不联网采集；所有数据为虚构模拟；
- 无真实 LLM、无多轮对话（助手为单轮规则生成，面板可留输入框样式但标注"演示版不支持对话"或直接不做输入框）；
- 不做复杂技术指标（MA/MACD/KDJ 等）与多只股票切换；
- 无服务端、无数据库、无持久化（不需要 localStorage）；
- 不提供任何投资建议、涨跌预测、买卖点。

| 前端零依赖测试方案（node:test vs Vitest） | 测试是提交硬要求，方案要与"自包含"一致 | 02 文档第 5 节 |
| A 股交易时段规则（集合竞价/连续竞价/盘后定价） | 时间映射的边界划分必须有权威依据 | 03 文档第 1 节 |
| 上市公司信披时段（盘后/晚间/非交易日披露窗口） | 模拟公告时间戳要符合真实披露习惯 | 03 文档第 2 节 |
| 异动判定阈值（龙虎榜 ±7%、振幅 15%、换手 20%；事件研究法 AR/CAR） | 异动阈值不能拍脑袋，需有规则与学术双重参照 | 03 文档第 3 节 |
| 事实/观点/因果的标注与证据分级方法论 | 题目四类标签的判据需要可辩护的框架 | 03 文档第 4 节 |
| 同类产品与开源项目（K-Ray、SPA 论文、alphai、TradeTheEvent 等） | 借鉴架构、数据模型、护栏措辞，避免踩坑 | 04 文档 |
